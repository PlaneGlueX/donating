# The client and the bag (2026-10-12)

Checked in the 26.3 client jar (`scratchpad\mc263`), Paper 26.1.2 build 74 (`server\versions\26.1.2\paper-26.1.2.jar`), ViaVersion 5.12.0, WeaponMechanics/MechanicsCore 4.3.1 and our own scripts. Dumps: `hands\client\jp\` (client, ViaVersion) and `hands\client\jpp\` (Paper).

## Short answer

- **The bag can be hidden during a reload.** No item-model property can read the main hand. Two server-driven signals do reach the offhand bag's item definition:
  - a cooldown on the bag's own cooldown group;
  - the item the client believes is in its offhand.
- **Recommended (realistic): option B, a look-alike bag only the holder receives.**
  - When the reload starts, GunFx sends the holder a copy of their bag whose `item_model` draws nothing in first person. When it ends, it sends a copy that draws normally.
  - Both copies have `hand_animation_on_swap: true`, so the client's own swap animation slides the bag down and back up, smooth every frame.
  - The server inventory never changes: Skript, the watchdog, bag.sk and WeaponMechanics see nothing, and the HUD shows no cooldown sweep.
  - Not yet tried in the client. Size: about 50 lines in GunFx plus 4 item definitions generated by build-pack.js.
- **Cautious: option A, a cooldown on `minecraft:leather` and `minecraft:paper`.** These are the bag's and the cash's default cooldown groups.
  - It uses the same mechanism GunFx already uses for every gun frame: about 10 lines plus a pack wrapper.
  - The cost is visible: the offhand hotbar slot (and the inventory screen) shows the white reload sweep, and the bag pops out and in instead of sliding.
- **Hands inside the gun models are feasible.**
  - Minecraft never draws the arm while a hand holds an item, so hands must be boxes in our own models with our own textures (an item model can't use the player skin).
  - `display_context` keeps them in first person only.
  - Each part's `transformation` places them anywhere: unlike the display transform and the element box, it has no limits (section 4).
- **Side finding:** the pack's `paper.json` (the cash in hand) lacks `"hand_animation_on_swap": false`, so the cash dips and rises every time its fill changes. `leather.json` has the flag.

## 1. How 26.3 draws the two hands in first person

- **Item swaps.** `FirstPersonHandsAndItems.tick` keeps the drawn main-hand and offhand stacks, each with an equip height from 0 to 1.
  - A new stack is shown at once when `shouldInstantlyReplaceVisibleItem` holds: `ItemStack.matchesIgnoringComponents(old, new, DataComponentType::ignoreSwapAnimation)` (only `damage` is ignored), or `!ItemModelResolver.shouldPlaySwapAnimation(new)`. The latter reads the new stack's `hand_animation_on_swap`; a stack without `item_model`, such as air, counts as true.
  - Otherwise the old item sinks by up to 0.4 a tick, swaps below 0.1, and the new one rises: about 3 ticks down and 3 up.
- **Which hands are drawn.** `evaluateWhichHandsToRender` returns `RENDER_BOTH_HANDS` unless a bow or crossbow is involved; a charged crossbow in the main hand draws the main hand only. **A non-empty offhand is always drawn, whatever the main hand holds.**
- **The offhand's display context.** `extractRenderState` resolves the offhand with `ItemModelResolver.updateForTopItem(state, offHandItem, FIRST_PERSON_LEFT_HAND, level, owner = LocalPlayer, seed)`; left-handed players get `FIRST_PERSON_RIGHT_HAND`. Every property in the bag's definition is read with the local player as holder.
- **Drawing (`FirstPersonHandsAndItemsRenderer.submitHandsWithItems`).**
  - The hand sway is `(viewXRot − xBob)·0.1` and `(viewYRot − yBob)·0.1`.
  - The equip progress is `e = swapScale·(1 − lerp(partialTick, oldHeight, height))`, lerped every frame.
  - `submitArmWithItem` returns early while `isScoping` (spyglass), which hides both hands.
  - An empty stack draws `renderPlayerArm`, but only for the main hand of a visible player. An empty offhand draws nothing, and maps draw arms through `renderMapHand`.
  - Any other item draws only the item, never an arm: `applyItemArmTransform` translates by `(±0.56, −0.52 − 0.6·e, −0.72)`, then `ItemStackRenderState.submit` draws it.
- **Transform order.** `LayerRenderState.applyTransform` runs `ItemTransform.apply(leftHand, pose)` (translate, rotationXYZ, scale, translate −0.5; the left hand uses −tx, −ry, −rz), then `pose.mulPose(localTransform)` with the composed item-definition `transformation`.
  - Each composite layer uses its own model's display block (`CuboidItemModelWrapper`). Hand models must therefore inherit the gun's display through `parent: gun_<key>_base`.
- **Projection.** `GameRenderer.render3dHud` clears depth once, then calls `Projection.setupPerspective(0.05, far, hudFov, w, h)`.
  - `Camera.calculateHudFov` returns 70; only death and being under water or lava change it. The hands always render at a 70° vertical FOV, whatever the FOV setting or zoom.
  - Both hands share one depth-tested pass, so whichever is nearer wins.
- **Where the bag sits.** The tier-1 bag (`bag_1_3d`, display `[0,15,0]`, `[1,2.5,0]`, scale 0.3) covers screen x −0.96..−0.60 and y −1.03..−0.56, where −1 is the left or bottom edge.

## 2. What in an item definition can make the offhand bag draw nothing

| Property | What it reads (26.3) | Usable for a reload-only hide? |
|---|---|---|
| `display_context` | the display context | Only always-on or always-off by itself; combine with a row below. |
| `cooldown` | `Cooldown.get` → `owner.getCooldowns().getCooldownPercent(stack, 0)` | **Yes.** Server-set and per player. The group is the stack's `use_cooldown` group, else the item id (`ItemCooldowns.getCooldownGroup`). Read once a tick, it runs from 1 down to 0, and is always 0 on other players' clients. |
| `custom_model_data` / `component` / `has_component` | the stack's own data | **Yes, but only by changing the stack**, either for real (C) or for the holder only (B). |
| `using_item` | `IsUsingItem`: the holder is using this stack | No: leather can't be used. |
| `keybind_down` | the client's own keys | No: the server can't set it, and the reload key is a tap. |
| `selected` / `carried` | the selected hotbar stack or the cursor | No: never true for the offhand. |
| `main_hand` | `getMainArm()` (which arm, not which item) | No property reads the other hand's item. |
| `view_entity` | `getCameraEntity() == player` | Hides every first-person item at once (CarCam's trick). |
| `fishing_rod/cast` | `player.fishing != null` plus `FishingHookRenderer.getHoldingArm` | Technically true for the offhand bag with a gun in the main hand. Needs a fake hook entity that draws a fishing line and bobber, so rejected. |

## 3. Ways to hide the bag during a reload

### (a) Cooldown on the bag's group (cautious)

GunFx calls `p.setCooldown(Key.key("minecraft:leather"), T)` and the same for `minecraft:paper` when the reload starts. It sets 0 on complete, cancel, slot change, death, quit and plugin disable. The pack wraps each bag case and the cash case:

```json
{"type":"minecraft:select","property":"minecraft:display_context",
 "cases":[{"when":["firstperson_righthand","firstperson_lefthand"],
   "model":{"type":"minecraft:range_dispatch","property":"minecraft:cooldown",
     "entries":[{"threshold":0.0001,"model":{"type":"minecraft:empty"}}],"fallback":BAG}}],
 "fallback":BAG}
```

- **Flicker:** none; the bag pops on tick boundaries.
  - More thresholds can slide it (rendered), but the share left `p = (end − now)/(end − start)` scales with the reload length and the shotgun restarts it on every shell. Keep it on/off.
- **Desync:** none. The cooldown is authoritative, sent in the same tick as the gun's clock, and expires by itself if GunFx forgets.
- **Cost:** two tiny packets per reload.
- **The sweep.** `Hud.extractItemHotbar` → `extractSlot` → `GuiGraphicsExtractor.itemDecorations` → `itemCooldown` fills `0x7FFFFFFF` over any slot whose stack is on cooldown. That includes the offhand slot, and `AbstractContainerScreen.extractSlot` does the same in inventory screens. It would run in step with the gun slot's sweep.
- **Other side effects:** none in practice. Leather and paper have no use action, so a cooldown only refuses their own use.
- **Watchdog and bag scripts:** untouched.

### (b) A fake offhand that only the holder receives

- **How the server syncs the offhand.**
  - Own slots go out as `ClientboundContainerSetSlotPacket(0, stateId, 45, item)` (`ServerPlayer$1.sendSlotChange`).
  - The server remembers what it sent in `remoteSlots` and resends only when the real item changes (`broadcastChanges` → `synchronizeSlotToRemote`) or on a full resync.
  - `sendAllDataToRemote` runs on every menu open, after a click with a stale state, and on `updateInventory`, and calls `sendOffHandSlotChange()`. `handleContainerClick` also resends the offhand after F (button 40) in another menu.
  - A cancelled F (`handlePlayerAction`, cancelled `PlayerSwapHandItemsEvent`) sends nothing.
  - Nothing else resends it: WM, MechanicsCore, our scripts and DonatingPhone never call `updateInventory`, and WM's `OutSetSlotBobFix` only acts for clients older than 1.21.4.
- **The cleanest fake:** `p.sendEquipmentChange(p, EquipmentSlot.OFF_HAND, copy)`.
  - `CraftPlayer.sendEquipmentChange` has no self-check and sends `ClientboundSetEquipmentPacket`.
  - The client's `handleSetEquipment` → `LivingEntity.setItemSlot` → `PlayerEquipment` writes the local player's offhand.
  - ViaVersion maps the player's real entity id to the 26.3 client's fake self id on `SET_EQUIPMENT` (`EntityPacketRewriter26_2.toFakeEntityId`).
- **Air: don't use it.** The bag would slide out, but `Hud` draws the offhand frame only for a non-empty offhand, so the whole HUD slot would vanish.
- **B, recommended: a look-alike.**
  - At reload start, send a clone of the real offhand with `item_model` = `donating:bag_hidden` (`hands_hidden` for the cash). It is leather.json's tree with first-person contexts set to `minecraft:empty` and `"hand_animation_on_swap": true`; GUI and third-person look unchanged.
  - At the end, send a clone with `donating:bag_shown`: leather.json's tree with `hand_animation_on_swap: true`.
  - Real → hidden slides the bag down over 3 ticks. Hidden → shown spends 3 invisible ticks, then the bag rises over 3, so send the shown copy about 3 ticks before WM's reload ends. A later real resync (shown → real) is instant and identical, because leather.json's flag is `false`.
  - **Remaining flicker:** a real resync while hidden (bag.sk redrawing the fill, a menu opening) pops the real bag back. Fix: while hidden, check once a tick whether the real offhand is still `isSimilar` to the copied source, also listen to `InventoryOpenEvent`, and re-send the hidden copy at that tick's end (`ServerTickEndEvent`, as CarBundle does).
  - **Desync risk:** if a restore were missed, the bag stays invisible in first person until the next resync (loot change, menu, respawn, rejoin). Harmless; restore all hidden players in `onDisable`.
  - **Cost:** two equipment packets per reload (a few hundred bytes each) and one `isSimilar` per tick for hidden players.
  - **Inventory screen and clicks:** pressing E opens the client's local screen, which shows the look-alike's normal icon. A click is cancelled by the lock, Paper resyncs, and GunFx re-hides.
  - **Watchdog and bag scripts:** untouched; no server slot ever changes.
  - **Triggers:** use WM's reload events, not GunFx's clock. The shotgun fires one event per shell, so hide on the first and show when `isReloading()` is false a tick after a complete or cancel event. Aiming mid-reload ends GunFx's frame clock but not the WM reload, so the bag stays hidden.

### (c) A flag on the real bag

GunFx sets a `custom_model_data` flag and the pack draws nothing in first person while it's set. It works with no sweep, but is strictly worse than B:
- Each reload changes the real stack twice, and each change sends a slot packet, broadcasts a `SetEquipment` to every tracker, and fires `PlayerInventorySlotChangeEvent`.
- The watchdog wakes (debounced to once a second). `repairLayout` reads only `itemId` (`bag:<tier>` / `hands`), so it leaves the bag alone.
- `bagRefresh`/`applyBag` drop the flag whenever the fill changes, so GunFx would have to re-flag every tick.
- A server stop mid-reload saves a flagged bag; `applyLayout` rebuilds it at the next join.
- The cash would dip on every flag change until paper.json gets `hand_animation_on_swap: false`.

### (d) Other routes, all rejected

- **The gun's own left arm covering the bag:** depth-tested and free, but a natural support arm leaves the screen around x −0.1..0.2 while the bag sits at −0.96..−0.60, so it never covers it.
- **Spyglass or "hands busy":** hide or lower both hands.
- **A foreign camera:** changes the whole view.
- **A charged crossbow as the main-hand item:** gives `RENDER_MAIN_HAND_ONLY`, but changes the gun's item type under WM, adds client crossbow prediction and arrows, and changes the third-person pose.
- **A fake fishing hook:** see the table in section 2.
- **Attributes or effects:** nothing touches the first-person offhand.

### Recommendation

Build B; build A instead if the smallest change is wanted first. Either can switch to "hide the bag whenever a gun is held" by triggering on the held slot instead of the reload. That's worth offering if the hands team also draws both hands at rest, where a bag floating in the corner would look odd.

## 4. Item model limits for arms reaching from the bottom edge

- **The frame** (render-item.js already matches it):
  - At depth d, the visible half-height is `h = d·tan 35° = 0.700·d` and the half-width at 16:10 is `w = 1.120·d`.
  - The item origins `(±0.56, −0.52, −0.72)` land at screen (±0.69, −1.03), just below the bottom edge, so anything below the grip is already off-screen.
  - Near plane 0.05: the AK-48's stock already reaches z −0.005 and is clipped there harmlessly.
- **Elements:** `from`/`to` must stay within −16..32 on every axis (`CuboidModelElement$Deserializer.getPosition`, else JsonParseException). Rotations are free (one axis at any angle, or euler `x/y/z`); `light_emission` is 0..15.
- **Display transform** (`ItemTransform$Deserializer`): translation is clamped to ±5 blocks (±80 px), scale to ±4; rotation is free.
- **Per-node `transformation`** (on `model`, `composite`, `select`, `condition`, `range_dispatch` and `special`; not `empty`):
  - `Transformation.EXTENDED_CODEC` takes a 16-float matrix or `{translation, left_rotation, scale, right_rotation}`. All four keys are required (`fieldOf`). Rotations are quaternions `[x,y,z,w]` or `{angle (radians), axis}`.
  - **It has no limits.** It composes parent → child at bake (`Transformation.compose`) and applies after the display transform.
  - So arms of any length or position work: author a hand as a small model along +x from 0 and place it with its part's transformation. The demo arm is built this way.
- **Reach without transformations** (`demo\reach.js`, each gun's default display): sample elbows off the bottom edge fit −16..32 for all nine guns. Points far to the left (camera x −0.45, or the bag's spot) fall just outside for the Machine Gun (z 32.1 and 33.4) and the Veteran (32.5); placing by transformation avoids the problem.
- **First person only:** `select` on `minecraft:display_context` with `["firstperson_righthand","firstperson_lefthand"]` → a composite of gun and hands, falling back to the gun alone. This nests inside build-pack.js's `view_entity` wrapper, so hands still vanish under the car camera.
- **Left-handed players:** the gun is drawn with `firstperson_lefthand` (−tx, −ry, −rz), which is the screen mirror of the x-flipped model. Hands built into the gun therefore appear on its other side, like the AK-48's charging handle. Keep hands roughly symmetric about the gun's centre plane. A negative scale would mirror them but also flips face winding (untested).
- **Textures:** an item model can't use the player skin (special `player_head` only draws a head), so hands need our own glove/sleeve texture. Give them their own texture variable (e.g. `#hands`): gun-skin child models only override `t`, so every present and future skin leaves the hands alone.
